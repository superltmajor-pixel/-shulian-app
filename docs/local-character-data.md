# 本地角色与公开源码

应用不内置角色。首次使用时在“恋人”页创建或导入自己的角色。

## 数据位置

默认角色库为 `%LOCALAPPDATA%\Shulian\role-library`，可用
`SHULIAN_ROLE_LIBRARY_DIR` 指向其他本地目录。正式版与其他产品应各自使用
独立的数据目录。角色库、SQLite 状态、媒体和凭据均不属于源码或更新包。

角色沿用稳定 ID，聊天、记忆、关系和已有存储键通过该 ID 关联。
每次保存生成新快照，旧快照保留。`profile.json` 存储前后端角色资料，
`extensions.json` 可保存结构化人格、背景依据、称呼、语音参数、初始关系
与日程；图片在快照 assets 目录中。程序只读取 JSON，不执行角色提供的脚本。

已有高级档案在普通编辑、停用和恢复时保留未在编辑器展示的字段。
高级角色的完整备份应复制整个本地角色库；当前“导出角色”ZIP 的范围仍为
基础编辑字段、头像/封面与聊天、记忆，不等同于高级档案的完整备份。
聊天数据库及媒体也需单独备份，不能只备份 Git 仓库。

## 开发与发布

- `.gitignore` 排除本地数据和角色素材。已跟踪文件仍必须从索引中删除。
- `python scripts/check-public-source.py` 检查工作树文件边界。
- `python scripts/check-public-source.py --staged` 检查完整 Git 索引。
- 使用 `git config core.hooksPath .githooks` 启用提交检查；CI 也执行相同检查。
- PyInstaller 只收集允许的通用前端文件，不收集角色图片、人格档案或运行数据。
- 新增通用 UI 位图时明确更新 `public_source.py` 白名单，不把私人立绘放回 web。

上述边界检查不能识别任意代码文本中手工粘贴的私人对话或凭据；提交前仍需
正常审阅差异。删除当前文件不会移除历史提交、标签、旧分支和旧发布附件。
首次公开前需要单独处理历史并确认项目许可证及第三方许可告知。

### 创建无旧历史的候选仓库

在开发仓库执行（目标目录必须不存在，且位于开发仓库之外）：

```powershell
python scripts/export-public-source.py --destination 'C:\Projects\shulian-public-candidate'
```

脚本只从当前工作树的 Git 已跟踪文件与未忽略新文件中复制允许的源码，包含尚未提交的改动，跳过已删除文件。
不会复制 `.git` 历史、运行数据、虚拟环境、构建缓存、本机 Agent 规范或系统诊断记录。
未审阅的路径、私人数据路径和符号链接会阻止导出；目标目录不会被覆盖。
新仓库只执行初始化和本地提交检查配置，不提交、不配置远端、不推送。
导出清单和逐文件 SHA-256 位于候选目录旁的同名 `.manifest.json`，不进入候选源码。

导出后应核对文件清单、内容权利与潜在凭据，在候选目录安装开发依赖并执行前端检查和隔离离线测试。
路径白名单不能证明内容无个人数据或拥有著作权；人工来源确认及实际发布授权仍需完成。
后续导出可指定新的候选目录，复用相同边界，不再重复手工删除角色素材。
